Phase 4 — Capability Execution Layer (The Real Work Begins)
This phase adds the final missing pieces:

Capability invocation

Input resolution (@step.output)

JSON merging

Output propagation

Trace streaming

Dashboard integration

Once Phase 4 is complete, the engine becomes a fully sovereign, deterministic, multi‑language execution runtime.

Let’s break it down cleanly.

1. Capability Registry (The Sovereign Function Table)
You already have the registry infrastructure. Now formalize it:

cpp
using CapabilityFn = std::function<nlohmann::json(const nlohmann::json&)>;
Registry responsibilities:
Register capabilities by (module_id, capability_name)

Lookup during graph construction

Reject pipelines referencing missing capabilities

Provide a clean, deterministic invocation surface

Engine API:
cpp
void Engine::register_capability(
    const std::string& module,
    const std::string& capability,
    CapabilityFn fn
);
This is the SDOA equivalent of linking sovereign modules.

2. Input Resolution (The @step.output Mechanism)
Pipeline steps can reference previous outputs:

json
"input": {
    "buffer": "@read_file.output"
}
Resolution rules:
If value is a string starting with "@":

Parse "@step_id.field"

Fetch runtime_graph[step_id].output[field]

If value is an object:

Recursively resolve fields

If value is a primitive:

Pass through unchanged

Implementation:
cpp
nlohmann::json resolve_inputs(
    const nlohmann::json& template,
    const RuntimeGraph& graph
);
This gives you dynamic dataflow.

3. JSON Merging (The Output Propagation Layer)
Capabilities return JSON.
Steps consume JSON.
Pipelines often need to merge:

static input template

resolved references

capability output

Merge strategy:
Object + Object → deep merge

Array + Array → replace

Primitive → replace

This keeps behavior predictable and deterministic.

4. Capability Invocation (The Heartbeat)
Inside the worker loop:

cpp
auto resolved_input = resolve_inputs(step.input_template, graph);
auto output = step.fn(resolved_input);
step.output = output;
Error handling:
Wrap in try/catch

On exception:

set error_flag_

record first_error_

decrement active_tasks_

notify main thread

This ensures no worker can poison the runtime.

5. Execution Trace Streaming (Dashboard Integration)
You already defined:

cpp
using TraceHookFn = std::function<void(
    const std::string& pipeline_id,
    const std::string& step_id,
    const std::string& event_type,
    const nlohmann::json& context
)>;
Emit events at key points:
Pipeline start:
cpp
hook(id, "", "PIPELINE_START", {});
Step start:
cpp
hook(id, step_id, "STEP_START", resolved_input);
Step success:
cpp
hook(id, step_id, "STEP_SUCCESS", output);
Step failure:
cpp
hook(id, step_id, "STEP_ERROR", { {"error", e.what()} });
Pipeline complete:
cpp
hook(id, "", "PIPELINE_COMPLETE", final_output);
This gives the dashboard a real‑time event stream.
